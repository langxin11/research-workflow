# 机器人动力学仿真与控制约定

以下约定按当前任务选用；沿用已有合理实现，不为局部修改重构项目。

## 仿真器与模型选择

- 沿用项目或论文合理方案，不从零重写通用物理引擎；通用接触仿真优先用 MuJoCo、Isaac、Newton 等主流引擎，用降阶或轻量模型做复现、控制设计与验证时须注明适用范围。
- 显式记录影响复现的仿真配置：
  - 产品、版本、运行模式（单环境/并行）与物理后端；
  - 物理步长 `dt_sim`、子步含义、控制与观测周期（如 `dt_ctrl`）及积分器/接触求解参数；
  - 执行器输入口径（直接关节力矩、限幅或传动比换算、底层 PD 目标）。

## 时序、分层与薄适配

- 明确实际物理步长、子步间指令保持方式（零阶保持或连续反馈）与观测/日志时间戳（步前或步后）；按引擎要求刷新运动学、雅可比与传感器等派生量，保留必要原生控制回调。
- 展示渲染不参与控制且不改变物理步进；批量对比支持无界面（headless）运行，传感器离屏渲染按观测时序执行。
- 用少量直观函数转换状态、观测和指令，直接调用仿真器或动力学库查询质量矩阵、偏置力与雅可比，不为未用到的引擎增加抽象层，避免多层继承、注册表与隐式包装。
- 明确控制器输入属于仿真真值、带噪/延迟观测还是估计量；使用真值时须标明假设。

# 控制周期主循环节拍示意（按所用仿真器原生 API 调整）
for step in range(n_ctrl_steps):
    t_obs = step * dt_ctrl
    obs = read_obs(sim)                  # 步前观测（含按观测时序的离屏渲染）

    for _ in range(n_substeps):          # n_substeps = round(dt_ctrl / dt_sim)

    log_step(t_obs, obs, u)              # 只记 t_obs 同拍量；若追加步后状态须另标 t_next

## 统一符号、公式与差异映射

- 在一处维护公共物理定义与符号—变量—公式映射（不强求跨项目统一公式；格式可参考 [项目说明模板](../assets/project-readme.md) 的“机器人动力学仿真约定”小节），须写明：
  - 维度、单位、坐标系及变换方向，以及力/力矩参考点与正号约定；
  - 关节顺序、四元数顺序，以及广义速度与姿态导数的关系。
- 复现多篇论文（如 `baseline 1/2/3`）时，各算法注释与推导可保留原论文符号以便核对，但须写清到公共约定的换号、坐标变换及项的拆分或合并（如偏置力与重力/科氏项对应）。

## 可理解性与复现节奏

- 编写控制器前先对齐核心公式、符号差异与论文缺失假设；核对作者代码时，重点确认坐标系、姿态/关节顺序、控制周期与执行器口径是否与论文一致。
- 每个 baseline 独立、扁平实现，宁保留少量直观重复也不强拆抽象；控制律按计算顺序组织（如适用：动力学项 → 误差与坐标变换 → 控制律 → 限幅；MPC/WBC 等 QP 控制器按构建与求解步骤组织）。
- 逐个打通单 baseline 最小闭环并核查物理趋势（位置/速度跟踪、力矩幅值，无外力与无输入时能量不应无故增加），再接入同一仿真环境、观测模型与评价口径横向对比。
